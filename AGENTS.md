# Команда Vocalis

Vocalis — локальное Windows-приложение: Electron/React/TypeScript и Python/RVC.
Прочитай `docs/ARCHITECTURE.md` и относящиеся к задаче разделы `docs/TESTING.md`.

## Постоянные специалисты

Профили находятся в `.codex/agents/`. Это профессии с постоянной ответственностью,
а конкретные задачи и изменяемые файлы назначаются на каждое поручение.

| Имя | Профессия | Когда привлекать |
| --- | --- | --- |
| `audio_engineer` | Аудиоинженер / разработчик AI | Качество RVC, задержка, буферы, CPU/GPU |
| `app_developer` | Разработчик приложения | Electron/Python, API, состояния, данные и интеграции |
| `ux_designer` | Дизайнер интерфейса и UX с реализацией | Сценарии, компоненты, уведомления, доступность |
| `release_engineer` | Инженер установки и релизов | Установка, зависимости, оборудование, сборки |
| `voice_specialist` | Специалист по голосовым моделям | Импорт, каталог, совместимость и примеры |
| `qa_engineer` | Тестировщик / QA-инженер | Воспроизведение, регрессии и независимая проверка |

## Работа координатора

Основной агент руководит разработкой. Для содержательных задач делегируй независимые
части подходящим специалистам; не запускай всю команду для небольшой правки.
Пользователь может явно поручить работу одному агенту или отключить делегирование.
Если клиент не предоставляет выбор именованного профиля, прочитай соответствующий
TOML и передай его `developer_instructions` обычному сабагенту вместе с поручением.
Если инструменты сабагентов недоступны, выполни работу сам и честно сообщи об этом.

Перед запуском назначь результат, критерии приёмки и владельцев изменяемых файлов.
Профессия не ограничена одним файлом. При пересечении изменений согласуй контракт
и последовательность; не допускай одновременной правки одного участка.
Учитывай фактический лимит среды, оставляя место основному агенту. Не создавай
дополнительных сабагентов внутри сабагентов без явного поручения координатора.
Не создавай пользовательские чаты вместо рабочих сабагентов.

Сначала согласуй изменения HTTP/WebSocket/IPC и форматов данных, затем разделяй
реализацию. Координатор проверяет общий diff, интеграцию и итоговую готовность.
Аппаратные тесты микрофона, GPU и виртуального кабеля выполняются последовательно.
Повторяемые решения сохраняй в документации проекта: не полагайся на память чата.

## Общие требования

- Сохраняй чужие незакоммиченные изменения. Не откатывай и не форматируй посторонний код.
- Выполняй только согласованную задачу. Список идей не является поручением реализовать их все.
- Сохраняй локальную обработку аудио и токен доступа к API на loopback.
- Не публикуй пользовательские модели, записи, секреты или содержимое локальных хранилищ.
- Учитывай `MODEL_POLICY.md` и `THIRD_PARTY_LICENSES.md`; изменение политики требует явного решения пользователя.
- Не меняй глобальные настройки Codex, модели и права доступа ради отдельной задачи.
- Сборка, публикация и установка драйверов — разные действия; выполняй только авторизованные.
- Проверяй затронутое поведение подходящими командами из `docs/TESTING.md`.
- Отчёт специалиста: результат; причина/решение; изменённые файлы; выполненные проверки
  и их результат; ограничения; что требуется от другого специалиста.
- Отличай проверенное автоматически от аппаратно проверенного и предположений.

Руководство для владельца проекта: `docs/TEAM.md`.
