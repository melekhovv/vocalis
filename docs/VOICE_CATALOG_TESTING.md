## Повторяемые команды

Из корня проекта:

```powershell
.\scripts\check-release.ps1
.\scripts\test-clean-releases.ps1
.\scripts\test-export-source.ps1
cd app
npm run typecheck
npm run build
node --test tests/main-lifecycle.cjs
node --test tests/cable-setup.cjs
node tests/ui-regression.cjs
cd ..\engine
.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
```

Для браузерной проверки нужны Playwright и Chrome/Chromium. При необходимости задать `PLAYWRIGHT_MODULE` и `BROWSER_EXECUTABLE` путями к установленным компонентам; сами тесты не открывают микрофон. Снимки сохраняются в исключённом из Git `app/tests/out`.

Независимые security-regressions можно выполнить отдельно:

```powershell
cd engine
.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_catalog_security.py" -v
```

Тесты импортируют `tests/_test_env.py` до импорта сервера и создают уникальное временное `VOCALIS_DATA_DIR`. Не подставлять пользовательские модели/записи в fixtures и не запускать тесты против рабочего пользовательского хранилища.

## Обязательные сценарии перед аппаратной приёмкой

1. Проверить текущий манифест и документы прав: для выбранного голоса должны быть CC0 на веса и записи, evidence, дата проверки, immutable revision, размеры и SHA-256. Пока одобренных записей нет, этот сценарий остаётся BLOCKED; не включать удалённую карточку в разрешённые только ради прохождения теста.
2. На временном профиле Windows открыть каталог, найти модель, проверить метаданные/права, установить, отменить загрузку, повторить, пережить сетевой сбой, перезапустить приложение. Проверить появление только завершённой совместимой модели в библиотеке и сохранение после перезапуска.
3. Повторить установку того же ID: не должно быть второй задачи или перезаписи модели. Удалять только явно выбранную тестовую модель. Пока она загружается, работает в live или используется в preview, удаление должно быть запрещено. Повторный локальный импорт с одинаковым именем использует новый суффикс: дедупликация содержимого разных локальных импортов не заявляется.
4. После установки выбрать голос, сравнить одну локальную фразу в Balanced, High Quality и Low Latency на фиксированных устройстве/параметрах. Отдельно проверить CPU и поддерживаемую NVIDIA; AMD GPU acceleration этой сборкой не поддерживается. Зафиксировать `inferMs`, `realtimeFactor`, `inputDrops`, `outputUnderruns`, `bufferMs`, слышимые обрывы и согласные. Показатель `totalLatencyMs` не является измерением микрофон → Discord.
5. Проверить VB-CABLE/Discord после отдельного авторизованного запуска драйвера и ручной перезагрузки, затем обновление/удаление установленного Vocalis с сохранением тестовых моделей и настроек. Не использовать реальные пользовательские записи как публикуемые доказательства.

## Ограничения безопасности

`weights_only=True` исключает обычное исполнение pickle-объектов; проверяются размеры файла, архитектура, формы тензоров и конечность весов. SHA-256 фиксирует проверенный файл, но сам по себе не гарантирует его безопасность. PyTorch и FAISS остаются сторонними нативными парсерами внутри процесса движка, без OS sandbox и отдельного лимита памяти процесса. Размерность FAISS не подтверждает, что индекс обучен для конкретных весов. Эти границы нельзя описывать как абсолютную безопасность любого `.pth`/`.index`.

Операции публикации GitHub, установки драйверов и реальные пользовательские хранилища не входят в автоматический QA этого каталога. До отдельного разрешения ничего не публиковать.
