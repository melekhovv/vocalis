# Команда агентов Vocalis

Руководство владельца проекта · 3 ноября 2026 года

## Что настроено

В проект добавлены шесть постоянных профессиональных профилей Codex в
`.codex/agents/`. Основной агент в чате выступает руководителем разработки.
Общие правила команды находятся в корневом `AGENTS.md`.

Постоянство означает сохранённые обязанности и инструкции. Исполнитель запускается
под конкретное поручение и не работает в фоне постоянно. Профили не создают шесть
отдельных приложений, аккаунтов или чатов в боковой панели. Решения между запусками
сохраняются в коде и документации; отдельная долговременная память не настроена.
Модель и уровень рассуждений в профилях не переопределены: используются настройки
родительской сессии. Фактический параллелизм ограничивает среда Codex.

## Кто работает в команде

| Имя для обращения | Работник | Главный результат работы |
| --- | --- | --- |
| `audio_engineer` | Аудиоинженер / разработчик AI | Стабильный звук и измеримая производительность |
| `app_developer` | Разработчик приложения | Надёжная совместная работа всех частей |
| `ux_designer` | Дизайнер интерфейса и UX | Понятный и реализованный пользовательский сценарий |
| `release_engineer` | Инженер установки и релизов | Воспроизводимая установка и проверяемая сборка |
| `voice_specialist` | Специалист по голосовым моделям | Совместимые модели и организованная библиотека |
| `qa_engineer` | Тестировщик / QA-инженер | Независимые результаты проверок и описания ошибок |

## Аудиоинженер / разработчик AI

Отвечает за RVC, качество преобразования, pitch, VAD, буферы, задержку, наушники,
виртуальный вывод, прогрев и использование CPU/GPU. Может менять разные модули,
если это нужно для согласованной аудиозадачи.

Примеры поручений: «Найди причину пропадания начала фразы», «Проверь необходимость
прогрева CPU», «Уменьши задержку, сохранив качество», «Определи причину перегрузки».

Сдаёт объяснение причины, исправление и сравнение до/после в указанных условиях.
Если реальная речь или оборудование не проверены, прямо сообщает об этом.
Не отвечает единолично за установщик или визуальный дизайн.

## Разработчик приложения

Отвечает за Electron/Python, запуск и перезапуск движка, API, WebSocket, IPC,
фоновые операции, настройки, сохранение данных и подключение внешних сервисов.
Согласует технические контракты между интерфейсом и движком.

Примеры: «Исправь очистку лога после успешного перезапуска», «Сохраняй изображение
и описание голоса», «Реализуй кэш примеров», «Подключи согласованный API каталога».

Сдаёт работающий сценарий, обработку ошибок/отмены и совместимость сохранённых
данных. Алгоритмы звука согласует с аудиоинженером, UX — с дизайнером.

## Дизайнер интерфейса и UX

Отвечает за удобство и внешний вид, навигацию, компоненты, карточки, микшер,
уведомления, доступность и адаптацию окна. Сам реализует согласованные изменения
frontend с использованием существующей дизайн-системы.

Примеры: «Сделай предупреждение о кабеле заметным», «Покажи перегрузку без спама»,
«Убери лишнюю прокрутку», «Предложи персонализацию карточек».

Сдаёт реализованный интерфейс со состояниями загрузки, ошибки и успеха. Проверяет
маленькое окно и масштаб Windows, когда доступна визуальная проверка.
Не придумывает технические статусы и проценты установки без данных движка.

## Инженер установки и релизов

Отвечает за Windows-установку, Python/uv, зависимости, диагностику компьютера,
обновление, версии и состав сборки. Исследует совместимость оборудования.

Примеры: «Добавь этапы установки зависимостей», «Проверь готовность компьютера»,
«Исследуй поддержку AMD», «Подготовь установщик», «Проверь установку VB-CABLE».

Сдаёт воспроизводимые команды, результаты проверок и перечень реально проверенных
конфигураций. NVIDIA, AMD и CPU рассматриваются по возможностям backend; ноутбук
сам по себе не отдельный backend. Установка драйвера и публикация релиза требуют
соответствующего поручения, подготовка сборки их автоматически не включает.

## Специалист по голосовым моделям

Отвечает за RVC-совместимость, импорт, параметры голосов, каталог, метаданные,
источники и примеры звучания. Учитывает действующую политику моделей проекта.

Примеры: «Исследуй внешний каталог с API», «Организуй встроенные примеры без своего
WAV», «Разберись, почему модель не импортируется», «Проверь метаданные голосов».

Сдаёт проверенные сведения о модели/источнике и реализует согласованную часть
библиотеки. RVC преобразует запись; произвольное чтение текста потребует отдельного
синтеза речи. Доступная ссылка на модель не равна одобрению её публичной поставки.

## Тестировщик / QA-инженер

Отвечает за независимую проверку требований, воспроизведение ошибок, регрессии,
сценарии установки и обновления. По умолчанию не исправляет продуктовый код;
пишет согласованные тесты и возвращает ошибки исполнителям.

Примеры: «Проверь установку с нуля», «Проверь изменение примеров голосов»,
«Проверь перезапуск после ошибки», «Проверь сборку перед выпуском».

Сдаёт результаты «пройдено / не пройдено / не проверялось», команды, шаги
воспроизведения и ограничения. Автотест с фиктивными устройствами не заменяет
проверку настоящего микрофона, звука, Discord и сквозной задержки.

## Руководитель разработки

Основной агент принимает задачу от владельца, определяет критерии приёмки,
назначает специалистов и владельцев изменяемых участков, согласует общие API,
объединяет результаты и проверяет итог. Сам выполняет небольшие задачи, если
делегирование создаст больше работы, чем принесёт пользы.

Профессии могут пересекаться по файлам. Например, прогресс установки требует
инженера установки для событий и дизайнера для отображения; координатор заранее
согласует контракт. Одновременные конфликтующие правки не допускаются.
Аппаратные проверки выполняются последовательно. Всех шестерых запускать для
каждой задачи не нужно: обычно достаточно одного-двух исполнителей и QA.

## Как пользоваться

Можно обращаться обычным языком, не распределяя файлы вручную:

> Команда, добавьте прогресс установки зависимостей. Подключи инженера установки,
> дизайнера и тестировщика. Дождись результатов и проверь итоговую интеграцию.

> Поручи аудиоинженеру разобраться с задержкой. Сначала нужна диагностика и замеры,
> затем исправление. Тестировщик должен независимо проверить регрессии.

> Подключи специалиста по моделям для исследования каталога. Пока только исследуй
> источники и предложи варианты, загрузки и интеграцию не реализуй.

> Пусть разработчик приложения и дизайнер сделают сохранение картинки и описания
> голоса. После реализации передай результат тестировщику.

Для одного специалиста достаточно: «Поручи release_engineer проверить сборку».
Для работы без команды: «Сделай сам, без сабагентов».

В новом чате проекта Codex должен прочитать `AGENTS.md` и обнаружить проектные
профили. Текущая сессия может не обновить список именованных ролей автоматически:
открой новый чат в этом проекте для загрузки профилей. Если клиент предоставляет
только обычный запуск сабагента, координатор читает профиль и передаёт инструкции
исполнителю вручную. Это сохраняет обязанности без зависимости от селектора ролей.

## Где менять обязанности

Профиль каждого специалиста: `.codex/agents/<имя>.toml`.
Правила координации и проверки: `AGENTS.md`.
Это руководство: `docs/TEAM.md`.

Настройка основана на официальной документации
[Codex: Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).
Файлы профилей используют обязательные поля `name`, `description` и
`developer_instructions`. Глобальная конфигурация пользователя не изменяется.
