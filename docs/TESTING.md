# Проверки

Из корня проекта после установки зависимостей:

```powershell
.\scripts\check-release.ps1
.\scripts\test-clean-releases.ps1
cd app
npm run typecheck
npm run lint
npm run build
node --test tests/main-lifecycle.cjs
node --test tests/cable-setup.cjs
cd ..\engine
..\app\build\bin\uv.exe run --with ruff ruff check vcengine
..\app\build\bin\uv.exe run --with pyright pyright --pythonpath .venv/Scripts/python.exe vcengine
.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
```

`app/tests/ui-regression.cjs` дополнительно требует Playwright. Можно задать пути через `PLAYWRIGHT_MODULE` и `BROWSER_EXECUTABLE`. Тест использует фиктивные модели и не открывает микрофон. Снимки из `app/tests/out/` исключены из Git.

`test-clean-releases.ps1` проверяет очистку старых установщиков на синтетических файлах во временной папке. Реальная папка `app/release` в этих тестах не используется. Проверяются сохранение новой сборки, удаление старых вариантов с суффиксами и распакованных копий, обновление контрольных сумм и отказ от удаления при неполной сборке или небезопасном пути.

Тесты движка используют временное хранилище и синтетический сигнал, созданный в памяти. Реальные голоса или аудиодатасеты для тестов не поставляются. Проверяются лицензирование каталога, импорт, preview локальной системной речи Windows (с подменой синтезатора), параметры, отмена/перезапуск, работа мониторинга, совместимость моделей и загрузки. Реальное звучание гарнитуры, Discord и сквозная задержка требуют отдельного аппаратного теста.

Регрессии оболочки проверяют сохранение журнала при неудачном перезапуске, очистку после READY и отмену установки. UI-регрессия проверяет уведомления о неверном выводе и устойчивой перегрузке, отсутствие дубликатов при обновлениях статуса и скрытие после остановки.

`engine/tests/test_voice_profiles.py` проверяет изоляцию параметров при A→B→A, модель без рекомендаций и индекса, сохранение и миграцию настроек, недеструктивную «Чёткую речь», сброс выбранного профиля, защиту от запоздалого изменения другого голоса и использование тех же параметров в preview. Это проверки управления настройками на фиктивных моделях: они не подтверждают похожесть тембра или разборчивость живой речи. Для проверки звучания на ноутбуке сравнить одну фразу в двух собственных моделях с прослушиванием в наушниках и отдельно записать показатели realtimeFactor, inputDrops и outputUnderruns до/после смены.

Перед релизом на чистой Windows последовательно проверить установку NVIDIA и CPU-профилей, отмену/повтор после сетевого сбоя, русский системный голос и прослушивание своей RVC-модели. На ноутбуке проверить CPU-подпись загрузки, доступность всех настроек при высоте окна 680 px, установку VB-CABLE пользователем из официального источника, выбор CABLE Input/Output и передачу звука в Discord. Эти проверки не выполняются автоматическими тестами и не требуют публикации пользовательских моделей или записей.

Для встроенной установки VB-CABLE проверить отдельно: установленный кабель скрывает предложение скачать; ошибка определения устройств предлагает повтор проверки; без подтверждения загрузка не начинается. Отмена загрузки и отказ в UAC должны оставлять возможность повторить действие. На чистой машине проверить скачивание, распаковку, проверку подписи, запуск установщика с UAC и обнаружение кабеля после ручной перезагрузки. Автоматические проверки подменяют сетевые ответы и запуск установщика; настоящий драйвер ими не устанавливается.
